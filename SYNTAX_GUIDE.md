## 1. Where things come from

| What you see | Where it comes from |
| --- | --- |
| Homepage name, subtitle, focus line, intro, sections | `index.md` |
| Sidebar name | `title:` in `index.md` |
| Project pages | Notes in `projects/` |
| Rows in a wikilinked list | The linked notes' frontmatter |
| Tag pages (`/tags/...`) | Tags in all notes, generated by Quartz |
| Footer links, "Site Map" label, colors, fonts | `quartz.config.yaml` (site-wide settings, not content) |

## 2. The homepage (`index.md`)

```markdown
---
title: Eddie Yang
role: Electrical Engineering @ University of Waterloo
focus:
  - Robotics
  - Controls
  - Embedded Systems
links:
  - "[GitHub](https://github.com/Sushidood)"
  - "[LinkedIn](https://www.linkedin.com/in/edward-yang-4a7599375/)"
  - "[Email](mailto:e234yang@uwaterloo.ca)"
---

Intro paragraph(s) go here.

## Featured Projects

<div class="wikilinked-list">

- [[Hall Effect Macropad]]
- [[Food Portioning]]

</div>

## Notes

- [[PCB Design]]
```

| Frontmatter | Required | Shows as |
| --- | --- | --- |
| `title` | yes | The large name at the top. Also used as the sidebar name and browser-tab name. |
| `role` | no | One line under the name. |
| `focus` | no | A small mono line: `Robotics · Controls · …`. It only wraps between items. |
| `links` | no | A row of links under the focus line. See [section 3](#3-the-links-row-links). |

The body:

- Everything after the frontmatter is shown below the header, as normal Markdown.
- `##` headings look like small uppercase section labels with a thin line under them.
- A first line `# <same as title>` is hidden, so the name isn't shown twice.

## 3. The links row (`links`)

Works on any note. On the homepage it shows in the header. On other pages it
shows as a row at the top of the page body.

```yaml
links:
  - "[GitHub](https://github.com/Sushidood)"
  - "[[Hall Effect Macropad]]"
  - "[[Hall Effect Macropad|my macropad]]"
  - "https://example.com"
  - "e234yang@uwaterloo.ca"
```

| Item | Result |
| --- | --- |
| `"[Label](https://…)"` | A link with your label. Opens in a new tab and shows a small `↗`. |
| `"[Label](mailto:you@x.com)"` | An email link. |
| `"[[Note]]"` | A link to that note, labeled with its `title`. |
| `"[[Note\|Label]]"` | A link to that note with your label. |
| `"https://…"` | A link labeled with the site name (for example `example.com`). |
| `"you@x.com"` | An email link labeled "Email". |

- **Keep each item in quotes.** Obsidian's Properties panel does this for you.
  Without quotes, YAML misreads `[...]`.
- If a `[[Note]]` doesn't exist, it shows as plain text.

## 4. Wikilinked lists (`wikilinked-list`)

Turns a bulleted list of `[[wikilinks]]` into rows in the style of Richard
Hua's featured projects: no card, just a thin line between rows. Works in any
note.

```markdown
<div class="wikilinked-list">

- [[Hall Effect Macropad]]
- [[Food Portioning]]
- [[Reaction Wheel]]

</div>
```

**Blank lines are required:** one after `<div ...>` and one before `</div>`.
Without them, the list is treated as raw HTML and the `[[links]]` won't work.

Each row is filled from the **linked note's** frontmatter:

| Part of the row | From the linked note | If missing |
| --- | --- | --- |
| Title | `title` | The note's file name |
| Date (right side) | `date` | Not shown |
| Description | `description` | The note's first sentence |
| Tags | `tags` plus inline `#tags` | Not shown |

- **Clicking:** click anywhere on a row to open that note. Each tag opens its
  own tag page.
- **Empty bullets** (`- ` with nothing after it) are removed.
- **Bullets that aren't a single wikilink** (plain text, two links, a link plus
  text) are left as normal bullets.

## 5. Colored links (`colored-links`)

Gives every link inside it a different color. Use a `span` inside a sentence,
or a `div` around whole paragraphs.

```markdown
I built a <span class="colored-links">[[Hall Effect Macropad]]</span> last term.

<span class="colored-links" style="--link-color: #d3869b">[[Food Portioning]]</span>

<div class="colored-links" style="--link-color: var(--gb-purple)">

A whole paragraph where [[every link]] and [external links](https://example.com) are purple.

</div>
```

- **Default color:** Gruvbox orange.
- **Custom color:** add `style="--link-color: <color>"`. Any CSS color works:
  `#d3869b`, `rgb(…)`, `tomato`, and so on.
- **Theme-aware colors:** these change shade between light and dark mode.

  | Variable | Color |
  | --- | --- |
  | `var(--gb-orange)` | orange (default) |
  | `var(--gb-red)` | red |
  | `var(--gb-yellow)` | yellow |
  | `var(--gb-green)` | green |
  | `var(--gb-aqua)` | aqua |
  | `var(--gb-blue)` | blue |
  | `var(--gb-purple)` | purple |
  | `var(--gb-gray)` | gray |

- Only links change color. Normal text stays the same.
- The `div` form needs the same blank lines as a wikilinked list.

## 6. Project notes (`projects/`)

Any note inside `content/projects/` gets the project page layout:

- **Header:** title, tags, date, description and hero image.
- **Below it:** your Markdown.
- **Right sidebar:** table of contents and backlinks.

```markdown
---
title: Hall Effect Macropad
description: A custom magnetic macropad designed from the ground up.
tags:
  - hardware
  - firmware
date: 2026-03-15
image: macropad.png
---

## Overview
...
```

| Frontmatter | Used for |
| --- | --- |
| `title` | The page heading, row titles, and labels for `[[links]]` |
| `description` | The lead paragraph under the heading, and the row description in wikilinked lists |
| `tags` | The tag pills in the header and in rows. See [section 7](#7-tags). |
| `date` | `2026-03-15` shows as "Mar 2026"; `2025` shows as "2025" |
| `hero` | A large image under the header |
| `image` | Used as the hero if there's no `hero`, and as the image in link previews when the page is shared |
| `links` | A links row at the top of the body. See [section 3](#3-the-links-row-links). |
| `cssclasses` | Extra CSS classes on the page (an Obsidian feature) |

Images (`hero` / `image`) can be written as:

- a file name: `macropad.png` (found anywhere in the vault, like Obsidian)
- a vault path: `attachments/macropad.png`
- a wikilink: `"[[macropad.png]]"`
- a URL: `https://…`

If the image can't be found, it is skipped.

A first line `# <same as title>` is hidden so the title isn't shown twice. The
table of contents also hides that heading.

Every field is optional. A project note with no frontmatter still works and
uses its file name as the title.

## 7. Tags

Tags work exactly as in Obsidian. Use either form, or both:

```markdown
---
tags:
  - hardware
  - robotics/arm
---

Text with an inline #firmware tag.
```

- **Both forms count.** Frontmatter tags and inline `#tags` are combined.
- **Same look everywhere.** Tags appear as small `#tag` pills in note bodies,
  the Properties box, project headers and wikilinked-list rows.
- **Tag pages.** Every tag links to Quartz's tag page (`/tags/hardware`), which
  lists every note with that tag. Nested tags (`robotics/arm`) also get a page
  for the parent tag (`robotics`).
- **Names.** Quartz turns tags into URL-friendly names: lowercase, with spaces
  becoming `-`. So `#PCB` is shown as `#pcb`. Writing tags in lowercase avoids
  surprises.
- **Tags in frontmatter don't need a `#`.** Inline tags do.

## 8. Normal Markdown that still works

All of this is standard Obsidian syntax and needs nothing extra:

| Feature | Syntax |
| --- | --- |
| Link to a note | `[[Note]]`, `[[Note\|custom text]]`, `[[Note#Heading]]` |
| Link to a website | `[text](https://…)` |
| Embed an image | `![[image.png]]` or `![alt](path/to/image.png)` |
| Highlight | `==highlighted text==` (muted yellow) |
| Callout | `> [!note] Title` on the first line, then `> text` on the following lines |
| Code | `` `inline` `` or a fenced block such as ```` ```c ````. Highlighted with the Gruvbox colors. |
| Math | `$inline$` and `$$block$$` (KaTeX) |
| Diagrams | A ```` ```mermaid ```` block |
| Comments | `%% hidden from the site %%` |

Callout colors:

| Callout types | Color |
| --- | --- |
| `note`, `info`, `todo`, `abstract` | blue |
| `tip`, `hint`, `important` | aqua |
| `success`, `check`, `done` | green |
| `question`, `help`, `faq` | yellow |
| `warning`, `caution`, `attention` | orange |
| `failure`, `danger`, `error`, `bug` | red |
| `example` | purple |
| `quote`, `cite` | gray |

## 9. Rules that apply everywhere

1. **Blank lines inside HTML blocks.** Any `<div class="…">` that wraps
   Markdown needs a blank line after the opening tag and before `</div>`.
   Inline `<span>` doesn't need them.
2. **Quote YAML values that start with `[`**, such as `"[[Note]]"` and
   `"[Label](url)"`.
3. **Write class names exactly:** `wikilinked-list` and `colored-links`.
4. **Previewing locally:** run `npx quartz build --serve` from
   `D:\Vaults\quartz` and open http://localhost:8080.
   - Note edits update the preview automatically.
   - After any change to the code in `plugins/`, stop the server and start it
     again.
   - **Only run one Quartz build or server at a time** from this folder. They
     share a cache file, and two running at once can crash the server with
     `buildQuartz is not a function`.
5. **Publishing:** run `npx quartz sync` from `D:\Vaults\quartz`. It copies your
   notes into the commit and pushes, and GitHub Pages rebuilds the live site at
   https://sushidood.github.io/quartz/.
